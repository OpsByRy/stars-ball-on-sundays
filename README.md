# Stars Ball On Sundays · public research website

This is the public presentation of SBOS's reviewed basketball research and recorded outcomes. It contains the website, brand assets, dated publication records with saved probabilities and projections, and standard odds/result utilities. Layups and Lobs show the approved selections beside Ry’s favorites. Bench is the depth chart of review-only props and stays outside official selection totals and hit/miss records. SBOS Research also includes reviewed Not a Pick lines. Same-day price updates append a new edition, retain earlier snapshots and label unavailable prices or changed value checks. The proprietary research engine, raw source candidate data, training data, calculation rules, and internal evaluations are maintained separately.

Run `python3 scripts/build.py` to validate every publication and build `dist/`. Preview only that directory with `python3 -m http.server 8001 --directory dist --bind 127.0.0.1`. Run `python3 -m unittest discover -s tests` and `node --test tests/*.test.cjs` before publishing. No API key or paid data connection is needed to build this website.

Only files listed in `site-manifest.json` and validated edition records are deployed. Data accepts a small explicit schema, rejects unknown fields at every nesting level, verifies content hashes, and includes box-score identities only for published selections. Never copy an engine checkout, raw slate export, CSV, technical handoff, diagnostic report, or research screenshot into this repository.

The public record distinguishes Ry's personal favorites from exploratory SBOS research. Missing original publication times remain unavailable. Statistical outcomes do not verify sportsbook settlement or establish profitability. See [About SBOS](https://starsballonsundays.com/about/) and the [evidence and results guide](https://starsballonsundays.com/guide/).

Research updates arrive as reviewed, sanitized records from the private publisher. Public code does not generate selections or infer model scores. The optional result refresher only checks already published contracts against public box scores; it cannot collect sportsbook odds or run the research algorithm.

Daily Board uses one tabbed list for All Daily Picks, Layups and Lobs, with a separate Ry’s Favorites filter. Essential search, probability and sorting controls stay visible; game, team and stat filters expand on demand. Research and Ry’s posted parlays have separate routes. Links preserve the board date and filter state, and the calculator keeps its selections within the browser session for each date.

The build derives small `data/boards/` views from the latest validated daily editions. These contain the selected props and personal attribution rows, with a `sourceVersion` pointing to the complete immutable edition. The separate Research page fetches the complete edition, including Not a Pick rows. Derived views never rewrite edition files or recalculate selections, prices, estimates or results.

Matchup headings use the saved game's exact date and event aliases for verified Away @ Home order. When that optional directory does not cover a slate, the pick's saved teams remain visible as Team vs Team with the existing approved logo artwork; missing home/away order does not mean missing teams. Missing opponents stay explicitly unavailable. Failed artwork requests retain the textual labels, and logo URLs remain restricted to the approved ESPN CDN.

Parlays uses a compact tabbed board for All Parlays, Plus Money and Longshots. Search and combined filters operate only on saved tickets; no list is truncated. Leg-estimate filters require every leg to meet the minimum and do not imply a joint win probability. Optional publisher-owned `ryFavorite` flags identify Ry’s favorite tickets; leg favorites do not automatically flag a parlay. Book preference reprices the same exact legs.

The Same Game Parlays filter covers saved same-game and mixed-game SGP combinations when reviewed tickets are available. The calculator accepts a user-entered full-ticket quote and clearly labeled probability scenarios. Straight-odds multiplication is only an independent benchmark; a quote gap is not a proof of value. Calculator assumptions are not validated SBOS joint forecasts, and no unvalidated research candidate is promoted into a published pick.

Research lets visitors combine player/team/line search, market, review category and probability coverage, with optional side and displayed-line filters. “With a saved probability” includes non-featured lines with a complete, timestamped pregame estimate for the recorded outcome. Held reviews, unavailable records and inconsistent forecast times are kept distinct; historical hit rates and projections do not become probabilities. Saved probabilities remain pregame snapshots after a game starts. Filters survive reloads and date changes through the URL, while the original Daily Board return state remains intact. Numeric searches match the displayed line; explicit comparison operators and milestones preserve their exact boundaries. Counts describe saved records, which may include equivalent lines from different sportsbooks.

The hosting build is `python3 scripts/build_hosts.py --publish`. It first runs the same validated public builder, then prepares `dist-cloudflare/` for `https://starsballonsundays.com` and `dist-github/` for GitHub Pages. `hosting-policy.json` uses redirect mode after the owned domain is verified. GitHub serves browser handoff pages, preserving known dates, filters and fragments; these are not HTTP 301 responses. Original immutable source files stay unchanged. A data JSON file exceeding Pages' 25 MiB limit is compacted in deployment copies by removing only formatting whitespace outside strings; every numeric/string literal token, value and edition version is preserved. The release receipt records separate original-source and deployed-file hashes, and the domain gate checks the compacted history files too. Files that still exceed the limit fail the build. Never deploy the repository root or private research source.

Cloudflare's `sbos-public` project automatically builds this public repository's `main` branch with `python3 -m unittest discover -s tests && node --test tests/*.test.cjs && python3 scripts/build_hosts.py --publish`, output `dist-cloudflare`, Python 3.12 and Node 22. Preview branch deployments are disabled. The result workflow keeps its existing schedule and records its actual final source commit so GitHub Pages checks out and tests that exact version. GitHub publication waits until the owned domain reports that same source SHA and passes page/history checks.

Before a new research publication, sync the public publisher checkout with current `main`, append the reviewed public records, and run the tests and publishing build. Push only the sanitized public repository. Cloudflare then builds the new main revision; verify `https://starsballonsundays.com/_sbos-release.json` reports that exact commit and check the dated board and archive. This workflow does not grant Cloudflare access to the private research repository or run the research engine.

Publishing uses saved, reviewed prices and shows “Odds refreshed at [time] ET” separately from forecast and posting times. Quote age alone, including a 15–30-minute build or review delay, does not block publication or add a stale banner. Known unavailable, materially changed or nonqualifying lines keep their Review state; no forecast or quote timestamp is retimed. The existing research and selection gates remain separate from publication timing.

An optional `publication-window.json` can pin the edition and its actual quote observation with `schemaVersion: sbos-publication-context-1`, `channel`, `date`, `editionVersion` and `quoteObservedAt`. The publishing build verifies the edition digest and matching saved quote clocks and rejects future observations. Legacy `sbos-publication-window-1` markers retain their recorded `validUntil` interval as audit context, without an age-only deployment block. After the first successful deployment, append an immutable posting-clock amendment using its actual completion time; preparation and verification times are different clocks.

Daily manifest `count` counts Ry’s personal rows; `researchCount` counts all reviewed research rows. Featured selections come from their saved categories. A date with 16 algorithm picks and no personal slips correctly has `count: 0`; do not replace it with the featured-pick count.

For newly selected pregame additions, `pending-additions.json` pins the exact new pick IDs and immutable edition. The publishing build checks those unposted selections against their scheduled game starts; it does not impose a quote-age deadline. Verify the actual first successful deployment completed before tip, then append its real posting clock to those new rows and remove the marker in a reviewed follow-up. Retain the original board's first-posting clock and every earlier row and edition. A new quote or forecast does not backdate an addition.

The domain gate waits up to 20 minutes for Cloudflare's build queue; its GitHub build job allows 30 minutes for tests, building and verification. If a release fails, retain the last healthy deployment and inspect Cloudflare's build logs and the GitHub publication gate. Revert the specific faulty change while preserving newer edition and result history. To restore GitHub's full site, set `githubMode` to `site` in a reviewed commit built from current main; do not reset the branch to an old data snapshot. Browser-local settings and installed app state belong to each origin and may need to be selected again on the new domain.
